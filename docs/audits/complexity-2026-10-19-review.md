# complexity.html 数据核验报告

核验日期：2026-10-19，中国时间。对象：`site/complexity.html`、`site/complexity.js`、`site/complexity.css`。

## 结论与核验边界

| 维度 | 结论 | 依据 |
| --- | --- | --- |
| 真实市场数据 | 不具备 | 页面明确声明全部为虚拟样例；HTML 与 JS 写死数值，未见行情加载和计算链路 |
| 演示数据内部一致性 | 未通过 | 存在最强边排序错误、跨图同名关系符号/数值不一致、初始化颜色不一致 |
| 数据可读性 | 需要整改 | 因素混列、指标定义不完整、图表尺度说明不足、部分字号过小 |
| 研究观察实用性 | 有设计价值，尚未形成可用数据工具 | 广度、分化、集中度和联动关系可构成观察框架，但真实数据、历史基准与计算口径未落地 |
| 投资决策实用性 | 未得到验证 | 无本页面指标的历史样本、样本外检验、稳定性与增量效果证据 |

本次检查包括逐行源码审查、用最小 document 桩执行原始 JS 的按钮回调，以及核对官方数据源说明。桩执行验证了数据更新逻辑，不等于真实浏览器 DOM、键盘或渲染测试。

浏览器安全策略拒绝 `file://` 协议访问。本次没有页面截图、桌面/移动端实际渲染、缩放、溢出和屏幕阅读器实测；关于这些项目仅报告源码可确定的属性或风险。没有绕过该限制。

页面及项目原有数据未修改。新增文件仅为本报告、核验脚本和 JSON 证据；没有启动全市场计算或行情采集。

## 一、数据真实性与来源适配

### 1. 所有显示值均为演示值，不能当作当天行情

`complexity.html:55` 的提示明确说明行情、数值、图表、关系网络均为虚拟样例。六张盘前卡片和四个系统状态指标直接写在 HTML；`complexity.js:1` 起的 20/60/120 日数据是对象常量。页面没有读取真实行情快照的路径，也没有本页面指标的计算实现。

因此，纳指 +0.72%、USD/CNH 7.1320、市场广度 46.2% 等不能归属于任何真实交易日。不能因为数值“看起来合理”就认定真实，也没有意义将其与 2026-10-19 的行情逐项比对。演示披露本身是清楚的，应保留。

目前“示意快照 · 中国时间 09:20”没有日期。真实版本需要分别记录市场观测时间、发布时间/可得时间、抓取时间和页面生成时间；仅显示 09:20 不能判断数据是否新鲜。

### 2. 官方来源确实存在，但并不等于页面数据已有来源

| 页面列出的来源 | 本次核对结果 | 对页面的影响 |
| --- | --- | --- |
| KRX Open API | 官方目录列出 KOSPI/KOSDAQ 等日行情服务；未从所链接目录确认 5 分钟服务 | 不能用这条链接证明 08:00–09:20 分钟行情已可获得。页面“分钟源待核验”的表述符合当前证据。[官方服务目录](https://openapi.krx.co.kr/contents/OPP/INFO/service/OPPINFO004.cmd) |
| Twelve Data | 页面链接定位于 market-state；供应商官方 SDK 将 `/market_state` 列为市场状态，将 `/time_series`、`/quote` 列为行情接口 | 市场开闭状态说明不能验证纳指/标普/半导体指数价格覆盖、套餐权限和实际返回值。原文档整页抓取超出工具大小限制，使用官方 SDK 参考作交叉核对。[官方接口列表](https://github.com/twelvedata/twelvedata-node/blob/master/api_reference.md) |
| 美国财政部 XML | 官方说明提供每日收益率数据及查询参数 | 可以作为“最近可用日值”候选，不能当成 09:20 实时收益率。还需明确具体系列、前值日期及 bp 的计算基准。[财政部 XML 说明](https://home.treasury.gov/treasury-daily-interest-rate-xml-feed) |
| LBMA Gold Price | 官方说明每天英国时间 10:30 和 15:00 定价，并列有使用/分发许可说明 | 基准价不是连续 XAU/USD 盘前现货流。应展示上一次基准的完整时间，或另选支持所需频率的报价源；页面目前没有证明已获相应权限。[LBMA FAQ](https://www.lbma.org.uk/prices-and-data/lbma-gold-price/lbma-gold-price) |
| EIA 现货价格 | 官方页面是日度历史现货表，且单独标示发布日期 | 不能直接作为中国时间 09:20 的 Brent/WTI 最新报价；现货与期货合约也应分开。[EIA 数据表](https://www.eia.gov/dnav/pet/PET_PRI_SPT_S1_D.htm) |
| A 股 | 仅描述待核对交易所/供应商权限，没有具体接口、快照及字段映射 | 广度、行业收益等尚不能溯源。项目其他模块即使已有真实数据，也不能自动证明本页面指标真实 |

## 二、已复现的数据一致性问题

P1 表示会影响读者对数值或关系的判断；P2 表示影响解释、操作一致性或阅读。这里不是交易风险评级。

### P1：60 日窗的“最强示例边”与自身数据矛盾

位置：`complexity.js:24`、`:28`；`complexity.html:222`。

60 日窗写的是“黄金 → 有色，0.41”，但同一组边权中“美股 → 电子”为 0.42。按显示的关联强度定义，0.42 大于 0.41。最强边应由同一份边表自动排序生成，不应独立写死文字。

### P1：网络与热力图对同名关系给出相反方向

网络方向由 HTML 中的 `cx-edge-negative` / `cx-edge-positive` 决定；JS 只调整线宽，没有根据有符号系数更新方向。核验将样式方向与 JS 强度合并后，对照热力图：

| 关系 | 20 日：网络 / 热力图 | 60 日：网络 / 热力图 | 120 日：网络 / 热力图 |
| --- | --- | --- | --- |
| 韩国 → 消费 | −0.17 / +0.17 | −0.12 / +0.12 | −0.08 / +0.08 |
| USD/CNH → 消费 | +0.12 / −0.12 | +0.09 / −0.09 | +0.04 / −0.04 |

后一项按 JS 键名 `consumer-fx` 对应 USD/CNH 比较；页面“汇率/商品”混列使其语义更不明确。如果实际采用了不同收益定义或控制变量，必须在页面显式标注，不能让读者猜测。

### P1：部分同名关系的强度也不一致

| 窗口 | 关系 | 网络强度 | 热力图 |
| --- | --- | --- | --- |
| 20 日 | 美股 → 新能源 | 0.24 | 0.21 |
| 120 日 | 美股 → 电子 | 0.31 | 0.35 |
| 120 日 | 美股 → 新能源 | 0.15 | 0.12 |

页面没有声明两个图使用不同统计量。应统一有符号系数的数据源；如确实不同，需要分别写明 Pearson/Spearman、滞后、控制变量及样本范围。

### P1：“汇率/商品”一列缺少唯一因素定义

位置：`complexity.html:262`。

列名同时涵盖 USD/CNH、黄金和原油；其 JS 键全部以 `-fx` 结尾。读者无法确认有色 +0.36、石油石化 −0.32 分别指什么。同列混入多个因素也不能横向比较。应拆成 USD/CNH、XAU/USD、Brent（或明确的合约/现货系列）独立列。

### P1：美债连线起点接错位置

位置：`complexity.html:190`、`:202`。

`rates-newenergy` 从 `(466,215)` 出发；美债节点位于 `translate(350 279)`，右侧中点约为 `(466,297)`。现有起点落在 A 股共同波动节点右侧范围，而非美债节点。此结论来自 SVG 坐标；未做渲染截图。它可能使读者把美债关系认作 A 股共同波动关系。

### P2：首次点击已选中的 60 日按钮，会改变 6 个未变数值的颜色

位置：`complexity.html:265` 至 `:268`；`complexity.js:66`。

初始 HTML 将 +0.09、+0.05、−0.05、+0.03、+0.07、−0.09 分别渲染为正/负色；回调则将绝对值小于 0.10 的数值设为中性色。初始页面没有调用 `setWindow(60)`，导致相同数据有两套颜色状态。

应统一初始化路径，并明确图例中“接近零”的阈值。这只是颜色分组阈值，不能冒充统计显著性阈值。

### P2：窗口控件实际作用范围不透明

点击 20/60/120 日会更换网络读数、线宽与热力图；折线图始终是固定 SVG，标题始终是“最近 60 个交易日”，四个 A 股状态卡也不变。

折线图使用固定历史展示长度并非必然错误，但应区分“关联估计窗口”和“历史展示区间”。目前热力图受网络区域按钮控制，却没有自己的当前窗口标记，容易在跨模块比较时误读。

## 三、统计口径与可读性

1. **市场广度不是同一个清楚定义。** 状态卡定义为“收盘价高于 20 日均线的股票占比”，折线图例却叫“上涨广度”。上涨家数占比与站上均线比例不能混称。还缺股票池、停牌/新股处理、复权口径、有效样本数与数据日期。
2. **“62/71 分位”缺历史参照。** 收益分化没有明确用横截面标准差、MAD 还是其他统计量；HHI 没有行业分类、是否互斥、份额分母及原始值；两项都没有历史分位的回看长度。应写成“历史第 62 百分位”，并提供原值与基准期。
3. **密度、平均强度和稳定关系无法复算。** JS 中它们分别是字符串常量，未定义候选边集合、连边阈值、平均是否取绝对值、稳定性的子窗口与最小样本。三个窗口始终绘制 12 条边，密度却变化；这不自动证明密度算错，因为可能存在未展示的候选边，但目前无法解释或验证。
4. **“行业同步性”与跨市场“网络密度”恰好都为 0.34，语义未区分。** 前者应基于行业间网络，后者包含外部节点与行业。两者不是同一指标，不能借相同数字暗示可互换。
5. **图表 0–100 尺度说明不足。** “归一化到 0–100 分位”没有写清是历史百分位还是线性归一化，也没有基准样本。卡片的比例、百分位、网络密度因此不能直接与曲线比较。曲线末点按图中坐标分别为 27.5、74、51.5，不是卡片 46.2、62、0.34；这本身不是已证实的数值错误，但需要转换公式才能判断是否对应。
6. **历史曲线无法逐日核对。** 每条曲线仅有 23 个折线顶点，没有日期、原始序列、抽样规则、悬停读数或数据表；“最近 60 个交易日”无法据此复现。23 个顶点本身不代表必然少数据，也可能抽样，但页面没有说明。
7. **若干重要文字过小。** CSS 中有 45 处 8/9/10px 字号声明，包括媒体查询重复项；不是 45 个实际元素。手机断点将指标脚注、网络图例等设为 8px。网络 SVG 缩放后，文字实际阅读尺寸还可能更小。建议优先放大数据口径、时间与图例；正文宜 14–16px，辅助说明尽量不低于 12px。
8. **局部横向滚动需要提示。** 热力图最小宽度 390px，来源表最小宽度 850px，外层有 `overflow-x:auto`。这说明窄屏需要局部横向滚动，不证明整个页面溢出。建议显示滚动提示或改为可展开的字段卡片；实际触控与溢出待浏览器验证。
9. **方法声明超出当前实现。** “口径透明，计算可复现”“指标……由明确公式与固定模板生成”尚无本页面实际公式管线支撑，应标为正式版目标或补齐实现。

已有可取之处：页面有醒目演示提示、来源接入状态、标题层级、跳转主要内容链接、可见焦点样式、表格 `scope`、按钮 `aria-pressed`；网络负向边使用虚线、热力格显示正负数值，提供了部分颜色之外的信息。这些结构应保留。折线图仍只有颜色区分系列和笼统 SVG 描述，建议补数据表/可访问读数。

## 四、实用性判断与整改顺序

这个框架适合回答：市场参与是否广泛、收益差异是否扩大、成交是否集中、行业共同波动是否增强、外部关系是否稳定。当前样例只能演示这些问题如何组织，不能回答当天市场实际处于什么状态，也不能证明外部因素对下一交易日有预测效果。

### 优先顺序

1. **先修一致性。** 使用一份有符号关系数据生成网络、热力图和“最强边”；修正美债边坐标；拆开汇率与商品；统一初始化颜色。
2. **先形成一个可核验的日频快照版本。** 明确每个系列标识、报价类型、单位、源交易日、观测/可得时间、延迟和缺失状态。无分钟源时展示最近可用日值，不标成盘前实时值。
3. **让指标可复算。** 公布股票池、复权、行业分类、计算公式、窗口、阈值和原始值；对每个真实快照保留输入来源与生成版本。所有图表、文字摘要来自同一份计算结果。
4. **支持读数和比较。** 增加上一期变化、历史中位/区间、样本数、有效覆盖率、数据下载；区分估计窗口与展示区间。放大辅助文字并实测移动端。
5. **再验证统计实用性。** 使用按当时可得时间对齐的数据做滚动样本外检验；区分收益与价格水平、收益率水平与 bp 变化。检查节假日、缺失、共同市场因素、极端值以及多重比较。若要宣称预测或配置价值，再比较加入外部因子前后的增量表现、稳定性和成本；相关图本身不提供这些证据。

### 可验收条件

- 每个真实数字能追溯到具体系列、日期、观测与可得时间；缺失和过期显式展示。
- 相同关系在各图的符号、系数、窗口和样本范围一致，或清楚解释不同口径。
- 最高强度关系、阈值筛选、密度及汇总指标可由数据自动重算。
- 初始状态与重复选择同一窗口一致；所有受控区域显示当前窗口。
- 原始指标、百分位转换及图表时间序列可下载或逐点读取。
- 桌面、窄屏、放大与键盘阅读完成实际渲染核验；本次这些项目仍待验证。
- 在获得实证结果前，保留“观察指标”的定位，不宣称经验证的预测能力。

## 五、复现与证据

在项目根目录执行：

```powershell
node docs/audits/audit_complexity.cjs
```

该脚本只读取三个页面文件，在最小 document 桩中执行页面原始 JS，并输出各窗口读数、跨图差异、初始颜色差异、SVG 坐标与源文件 SHA-256。它不访问行情源、不修改页面，也不验证真实布局。

本次输出保存在 `docs/audits/complexity-2026-10-19-evidence.json`。已执行 60 → 20 → 120 → 60 窗口回调，活动按钮和读数更新正常；上述矛盾可重复出现。三个源文件的摘要也已保存在该 JSON，便于确认报告对应版本。
